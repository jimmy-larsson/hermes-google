## 1. drive_get exports Google-native files (#900)

`get_file(service, *, file_id, cache_dir, export_mime_type=None)`:

- After the metadata call, a MIME type starting with `application/vnd.google-apps.` is a Google-native file. `application/vnd.google-apps.folder` raises `DriveError("cannot download a folder; use drive_list")`. `application/vnd.google-apps.shortcut` raises `DriveError("cannot download a shortcut; open its target file instead")`. Other native types export with `files().export_media(fileId, mimeType=<export type>)`; binary files keep `files().get_media`, and `export_mime_type` is ignored for them.
- The export type is `export_mime_type` when given, else the default for the type: document to `text/markdown`, spreadsheet to `text/csv` (Drive exports the first sheet), presentation to `application/pdf`. A native type with no default and no argument raises `DriveError("cannot download <mime>: pass export_mime_type")`.
- The raw Drive name passes the existing safety checks first; the cached file name is then that name plus the export format's extension (`.md`, `.csv`, `.pdf`, `.xlsx`, `.docx`, `.pptx` from a built-in map, else `mimetypes.guess_extension`), not doubled when the name already ends with it.
- The download loop is wrapped: a failure raises `DriveError(api_failure("export" or "download", exc))` and removes the partial file; errors from that cleanup are suppressed so the original failure is the one reported.
- Tool `drive_get(file_id, export_mime_type=None)`; the docstring states the defaults and the override.

## 2. Calendar errors carry the Google reason (#1113)

The five `raise CalendarError("failed to ...") from exc` sites in `core/cal.py` become `raise CalendarError(api_failure("<action>", exc)) from exc` with actions `list calendars`, `list events`, `create event`, `update event`, `delete event`. `user calendar not configured` and `unexpected create response format` stay.

## 3. The retry wrapper repeats a call only after an auth failure (#1122)

`_auto_retry` in `mcp_server.py` classifies a caught `ServiceError`: an `AuthError`, or a `ServiceError` whose `__cause__` is a google.auth `RefreshError` or an `HttpError` with status 401, means Google rejected the credential before the request executed (the case after a token is revoked and replaced while the server runs); the cached config and services are reset and the tool runs once more, with a second `ServiceError` converted to `ToolError`. Any other `ServiceError` becomes a `ToolError` immediately, so a request that reached Google (a create that timed out after being committed) is never repeated, and validation errors no longer reload the credentials. `auth_status` is unaffected. A refresh rejected by Google while loading the token (revoked or expired refresh token) raises `AuthError("credentials rejected by Google; run `hermes-google auth login`")` instead of a raw `RefreshError`.

## 4. Attachment cache hygiene (#1165)

New `core/cache.py`:

- `prune_cache(cache_dir, *, max_age_days=30, now=None) -> int` snapshots every entry's type and mtime before deleting anything, then deletes regular files older than the limit and removes directories that are empty and themselves older than the limit (so a directory a concurrent download has just created survives), skips symlinks, tolerates a missing directory and OS errors anywhere in the walk, and returns the number of files removed.
- `clear_cache(cache_dir) -> list[Path]` removes everything under the directory, keeps the directory, and returns the entries it could not remove.

`_get_services()` prunes once when it builds the services (the first tool call after a server start, and again after a credential reload). The CLI's `auth revoke` clears the cache after revoking the token, prints any leftovers instead of claiming a clean wipe, and exits non-zero when there are any. README gains a data-retention note with that timing. Rationale: Google's Workspace AI Tools Addendum caps retention of API-derived data at 30 days and requires deletion on disconnect; cached attachments are user data obtained through the APIs.
