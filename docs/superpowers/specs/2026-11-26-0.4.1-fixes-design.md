## 1. drive_get exports Google-native files (#900)

`get_file(service, *, file_id, cache_dir, export_mime_type=None)`:

- After the metadata call, a MIME type starting with `application/vnd.google-apps.` is a Google-native file. `application/vnd.google-apps.folder` raises `DriveError("cannot download a folder; use drive_list")`. Other native types export with `files().export_media(fileId, mimeType=<export type>)`; binary files keep `files().get_media`.
- The export type is `export_mime_type` when given, else the default for the type: document to `text/markdown`, spreadsheet to `text/csv` (Drive exports the first sheet), presentation to `application/pdf`. A native type with no default and no argument raises `DriveError("cannot download <mime>: pass export_mime_type")`.
- The cached file name is the Drive name plus the export format's extension (`.md`, `.csv`, `.pdf`, else `mimetypes.guess_extension`), not doubled when the name already ends with it. Name safety checks are unchanged.
- The download loop is wrapped: a failure raises `DriveError(api_failure("export" or "download", exc))` and removes the partial file.
- Tool `drive_get(file_id, export_mime_type=None)`; the docstring states the defaults and the override.

## 2. Calendar errors carry the Google reason (#1113)

The five `raise CalendarError("failed to ...") from exc` sites in `core/cal.py` become `raise CalendarError(api_failure("<action>", exc)) from exc` with actions `list calendars`, `list events`, `create event`, `update event`, `delete event`. `user calendar not configured` and `unexpected create response format` stay.

## 3. The retry wrapper repeats a call only after an auth failure (#1122)

`_auto_retry` in `mcp_server.py` catches `AuthError` first: reset the cached config and services, run the tool once more, and convert a second `ServiceError` to `ToolError`. Any other `ServiceError` becomes a `ToolError` immediately, so a request that reached Google (a create that timed out after being committed) is never repeated, and validation errors no longer reload the credentials. `auth_status` is unaffected.

## 4. Attachment cache hygiene (#1165)

New `core/cache.py`:

- `prune_cache(cache_dir, *, max_age_days=30, now=None) -> int` deletes regular files under the cache directory whose mtime is older than the limit, removes directories left empty, skips symlinks, tolerates a missing directory and OS errors, and returns the number of files removed.
- `clear_cache(cache_dir)` removes everything under the directory and keeps the directory.

`_get_services()` prunes once when it builds the services (so on every server start and after a token reload). The CLI's `auth revoke` clears the cache after revoking the token. README gains a data-retention note. Rationale: Google's Workspace AI Tools Addendum caps retention of API-derived data at 30 days and requires deletion on disconnect; cached attachments are user data obtained through the APIs.
